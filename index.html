1 Prompts

Up to 5 prompts, max 50 characters each. The widget cycles through them with a typing animation, one after another, on a loop.

On a phone there isn’t room for the label and a long prompt on one line, so “Ask Companion:” moves to its own line and the prompt gets the full width. Your longest prompt decides when that happens, so a set of short prompts stays on one line further down.

2 Colours

The gradient runs through the word Companion and the star beside it. The prompt text stays near-black, because it is the part people read.

Your colour sets the hue the gradient starts from, and the other two stops are worked out for you. Each one is darkened only as far as it needs to be to stay readable on a white page, so a pale brand colour comes back deeper than you picked it. Pick a grey and you get a grey gradient.

3 Image

Must be https://. Use an image already hosted on your marketing site, a CDN, or an asset URL you can copy from inside 360Learning.

Why this is the better option: the browser downloads a hosted image once and reuses it on every later visit. Embedded images can’t be cached, so they’re re-downloaded in full on every page load, by every learner, every time.

Use this when you have no hosting. The photo becomes part of the widget code, so it can never break, but it also can’t be cached: its full weight is re-downloaded on every page load. Prefer a hosted URL for a homepage with daily traffic.

Leave it empty if the image is purely decorative.

Widget code

Show the code
  1. Copy the widget code above. It’s self-contained HTML and CSS, no hosting or iframe needed.
  2. In 360Learning, edit either your homepage or the group page layout and select the HTML block (how to).
  3. Paste the code and click apply. Done.

The widget makes no external requests of any kind. It asks for Plus Jakarta Sans, uses it if 360Learning already serves it, and otherwise falls back to the reader’s own system font, which needs no download at all.

You can put several widgets on one page. Each one names its own styles after its own settings, so they can’t interfere with each other. The one thing to avoid is pasting the very same widget twice: two copies with identical settings are identical code, and on a Live training deck that means both sets of arrows drive whichever came first. Change anything at all on the second one, even the heading, and they work independently.

Reopen a widget from its code

Every widget this builder makes carries its own settings in a comment on the last line. Paste that code back here and the controls come back, so a widget already live on a page can be edited months later by someone who never had the share link.

An uploaded photo is the one thing that doesn’t travel: it would be far larger than the widget it sits in. A hosted image URL comes back fine.

Save the image

360Learning uses the media name as the alt text a screen reader announces, so describe the course rather than the picture. It also becomes the file name.

This browser cannot turn a cover into an image file, so Download will not work here. The previews above are accurate. Chrome, Edge and Safari can do it; Firefox currently cannot.

  1. Download the image, then upload it in 360Learning as the course or path cover.
  2. Give the media the same name you typed above. That name is the alt text.
  3. Check it on the course homepage, where only the middle band of the image shows.

A cover cannot be reopened from the image the way a widget can be reopened from its code. A JPEG carries no settings. Copy share link in the header is the way back to a cover you want to change later, so take one before you close the tab.
